# MEMORY.md

## Project Overview

Static educational site about IP networks (Redes IP) plus classroom tools (generador de contraseñas, tareas, notas, agenda). Pure HTML/CSS/JS — the site has no build step and no framework; a root `package.json` holds **dev-only** tooling (lint/format plus the test runner, see below) and a GitHub Actions workflow (`.github/workflows/check.yml`) runs it on every push to `main`/`herramientas` and on pull requests. Must be served over HTTP (`python -m http.server`): navigation uses `fetch()` and breaks on `file://`.

## Architecture

- `index.html` is the **only real entry point** and the only place with `<link>`/`<script>` tags (Bootstrap CDN + `scripts/*.js` + `css/*.css`). Its semantic skeleton is `<header>` (navbar) + `<main id="cuerpo">` + `<footer>`, a single `h1`; `#cuerpo` keeps its `id` so `cargarFragmento()` keeps working when the wrapper changed from `div` to `main`. The navbar's two dropdown toggles are native `<button type="button">` (not `<a role="button" href="#">`), which is what html-validate's `prefer-native-element` demands; Bootstrap 5.3's `.nav-link` already resets the button's `background`/`border`, so it looks the same.
- **Sync invariant:** the whole home portada (hero + cards + guide) in `inicio.html` is duplicated as the initial content of `#cuerpo` in `index.html`. Both copies must keep the **same tags and the same visible words** (character-for-character equality no longer holds: Prettier lays each copy out with different whitespace because they sit at different indentation levels, which does not change the render). Any edit to the portada must be applied twice.
- `inicio.html`, `teoria.html`, `clases.html`, `subneting.html`, `conversor.html`, `pass.html`, `tareas.html`, `notas.html`, `agenda.html` are **pure-markup fragments** (no doctype/head/body/link/script) injected into `#cuerpo` by `cargarFragmento()` in `scripts/redes.js`. **Each fragment opens with a single `<h1>`**, keeping its previous size with Bootstrap's size class (`.h2`, `.h5`, `.h6`), because `pintarHTML()` replaces the whole content of `#cuerpo`, the portada `h1` included; `test_fragmentos.js` guards one `h1` per view and that heading levels never skip. `teoria.html` is the theory tutorial (IPv4 basics, classes A–E, mask/CIDR, subneting with the `200.3.25.0/24 → /27` example, private/public addresses per RFC 1918, and a "Más lectura" list of external links). Its menu link ("Teoría") replaced the old paid Platzi link. `conversor.html` is the base converter (decimal, binary, octal, hexadecimal) under "Direcciones IP → Conversor Bases"; it validates per base and caps values at 32 bits (`0 … 4294967295`), which is what the IP octets need.
- **Key gotcha:** `<script>` tags inside an injected fragment never execute (fragments are parsed with `Range.createContextualFragment`, which does not run scripts either). That is why `cargarFragmento()` calls `inicializarFragmento(archivo)` after injection, which runs `prepararValidacionIP()` plus the per-fragment init function: `iniciarClases()`, `iniciarSubneting()`, `iniciarConversor()`, `iniciarPass()`, `iniciarTareas()`, `cargarNotas()`. New fragment with JS → register it there.
- **Navigation (HTML-05 closed):** there are **no inline handlers** in the markup. A single delegated `click` listener on `document` (`prepararNavegacion()` in `redes.js`, registered once at load, at the end of the file) resolves any element with `data-vista`, translates it through the `VISTAS` map (vista id → file) and calls `cargarFragmento()`. Because it lives on `document` it keeps working for every fragment injected later; `marcarVistaActiva()` only toggles `.active`/`aria-current="page"` on `.navbar-nav [data-vista]` links, so the portada links can share `data-vista` without getting highlighted (Bootstrap's `.btn.active` would restyle them). Tool controls are wired by `id` in the init functions (`btn-ver-clase` in `clases.html`; `maskSelect`, the mode radios `modo-capacidad`/`modo-objetivo`, `btn-clase`, `btn-capacidad`, `btn-redes`, `btn-hosts` in `subneting.html`; `base-origen`, `numero-convertir`, `btn-convertir` in `conversor.html`; `btn-guardar` and the already-JS-bound `btn-cargar` in `notas.html`).
- Tool scripts must not run DOM code at load time (elements do not exist yet); each init function attaches its listeners (`addEventListener`, or `.onclick =` when the same node is repainted and must not accumulate listeners).
- `scripts/`: `redes.js` (IP utilities, class detection, subneting calculators and their two modes — _capacidad_ and _objetivo_ —, tutor mode, **navigation** — the `VISTAS` map + the delegated click listener —, **and the site's single HTML sink**: `nodosDesdeHTML()` — a `Range.createContextualFragment` wrapper — plus `pintarHTML()`/`escribirResultado()`; only generated markup, never user data, goes through it), `scriptpass.js` (password generator + copy-to-clipboard with a `navigator.clipboard` → `execCommand('copy')` fallback for insecure contexts, i.e. http on the LAN), `scriptTareas.js`, `scriptConversor.js` (base converter: per-base regex validation instead of blind `parseInt`, 32-bit cap, binary grouped in octets, output rendered with `createElement`/`textContent`; all helpers live inside an IIFE that only publishes `iniciarConversor` on `window`; the result box is an `aria-live` region, the field points to its hint with `aria-describedby` and gets `aria-invalid` while the aviso is an error), `notas.js`.
- **Asistente de chat (sin backend):** `index.html` incluye, **fuera de `#cuerpo`**, el widget flotante `#chatWidget` (`.chat-widget`), con lo que sobrevive a cada inyección de fragmento. Es un **motor de reglas local**, no un LLM: no hay endpoint ni clave de API (cualquier clave enviada al navegador es legible). `scripts/chatDatos.js` contiene `BASE_CONOCIMIENTO` (entradas con `claves` ya normalizadas —minúsculas, sin acentos, `ñ` → `n`—, `pregunta`, `respuesta` y, opcionalmente, `vista` + `etiqueta`); `scripts/chat.js` normaliza el mensaje (`normalizarTexto`), puntúa cada entrada por la longitud de las claves encontradas como palabra completa (`puntuarIntencion`) y exige `UMBRAL_RESPUESTA` para contestar; si no llega, ofrece tres preguntas pulsables. `responder()` es `async` a propósito para que un endpoint pueda sustituir su cuerpo sin tocar la interfaz. Cuando la respuesta trae `vista`, la burbuja recibe un `<a data-vista>` que pasa por el listener delegado de `prepararNavegacion()` sin lógica nueva (`vistaValida()` comprueba el id contra `VISTAS` antes de crear el nodo) y el panel se cierra al navegar. El widget es marcado estático, así que `iniciarChat()` se ejecuta al cargar (no vía `inicializarFragmento`); los mensajes se pintan con `createElement`/`textContent` y se guardan en `localStorage` (clave `chat`, tope de 40). `css/chat.css` se limita a tokens del tema, por lo que funciona en claro y en oscuro. El panel es **no modal** (no atrapa el foco): `Escape` se escucha en `document`, no en el widget, para que cierre aunque el foco esté en otra parte de la página.
- **Persistence:** the tools save data in `localStorage` as JSON — keys `contrasenas` (`[{login, password}]`), `tareas` (`[{id, texto, completada}]`), `notas` and `chat` (`[{autor, texto, vista?, etiqueta?, sugerencias?}]`). Pattern: `leerX()`/`escribirX()` helpers with `try/catch` (private mode/quota), init function reloads from storage and repaints after every mutation. Stored passwords are plain text in the browser (classroom use only — noted in the UI). Rendering uses `createElement`/`textContent`, never `innerHTML` with user data (password charset contains `<`/`>`).
- `css/`: unified dark "NOC" theme. `tema.css` holds design tokens (`--red-*`, including the `--red-gradient` cian→teal accent) and overrides Bootstrap CSS variables (`data-bs-theme="dark"` on `<html>`, cyan accent, fonts **IBM Plex Sans** body + **IBM Plex Mono** data via `--red-font-body`/`--red-font-mono`); `estilos.css` is the layout (navbar, footer, agenda) + the **home portada**: a two-column hero (`.hero-redes`) with the IP-address signature (`address-signature`, octeto blocks), data chips (`.hero-chips`/`.chip`) and a hand-drawn inline SVG network illustration (`.hero-art`) whose data-flow packet animates along a path (offsets respected; disabled by the global `prefers-reduced-motion` rule) and whose mono labels take their color from the `.hero-svg-accent` / `.hero-svg-muted` classes instead of inline `style=`, plus the "Explora el sitio" feature cards (`.feature-card`, `.icon-circle`, `.card-link`, `.tool-pill`) and the three-step "¿Por dónde empiezo?" guide (`.step`/`.step-num`). `stylepass.css`, `tareas.css`, `notas.css`, `conversor.css` are scoped under `.vista-pass` / `.vista-tareas` / `.vista-notas` / `.vista-conversor` (their fragment wrapper) so `body`/`button`/`input`/`.container` rules don't leak site-wide. Layout uses two systems: `.panel` (slab, elevated — interactive tools) and `.field` (flat, hairline — explanatory content). The accent is a family of tokens: `--red-accent` (borders, icons, button background), `--red-accent-hover`/`--red-accent-active` (button states), `--red-accent-rgb` (focus ring) and `--red-on-accent` (text painted on an accent background). Light mode uses a darker accent (`#0e7490`, 5.1:1 on the page background) and white `--red-on-accent`, so accent text, links and button labels stay above WCAG AA. Because Bootstrap 5.3 styles links with `a { color: rgba(var(--bs-link-color-rgb), …) }`, the theme must set `--bs-link-color-rgb` and `--bs-link-hover-color-rgb` in both modes: `--bs-link-color` alone has no effect. `normalize.css` was removed (Bootstrap Reboot covers it). The whole home portada (hero + cards + guide) on `inicio.html` is duplicated as the initial content of `#cuerpo` in `index.html` and must stay in sync. Table headers are sentence case (no uppercase); `:focus-visible` and `prefers-reduced-motion` are handled in `tema.css`.
- Subneting is **classful**: classes A/B/C only, contiguous masks ≥ the class default, at least 2 host bits. Listings use 32-bit arithmetic (no manual carry). The calculator has **two explicit modes** (`aplicarModoSubneting`): _capacidad_ (default: with the IP and the mask — or the class default mask when none is given — `calculaCapacidad` summarises the possible subnets and useful hosts and points to the other mode) and _objetivo_ (`Redes`/`Hosts` derive the mask from a target number; empty fields now explain the alternative instead of a bare error). The `#result` box is an `aria-live="polite"` region.

## Dependencies

- Bootstrap 5.3.8, Bootstrap Icons and Google Fonts **IBM Plex Sans** + **IBM Plex Mono** (CDN). jQuery is not used.

## Accessibility and SEO

- `index.html` (the only entry point) carries `<html lang="es">` and a `<meta name="description">` (133 characters). All three jsDelivr resources — `bootstrap@5.3.8/dist/css/bootstrap.min.css`, `bootstrap-icons@1.11.3/font/bootstrap-icons.min.css` and `bootstrap@5.3.8/dist/js/bootstrap.bundle.min.js` — carry **SRI** (`integrity="sha384-…"` + `crossorigin="anonymous"`). Bumping a CDN version means recomputing the hash (`node -e` + `crypto`, over the response bytes the browser receives) or the browser blocks the asset. Google Fonts cannot take SRI (the CSS varies per user agent).
- **Skip link:** `<a class="skip-link" href="#cuerpo">` is the first node in `<body>`; `.skip-link` (in `estilos.css`, using theme tokens) is `position: fixed` off-screen and slides in on `:focus`, and `<main id="cuerpo">` has `tabindex="-1"` so it can actually take the focus. The delegated navigation listener ignores it (it has no `data-vista`), so the browser performs the jump.
- **Decorative icons:** the 62 `<i class="bi …">` in the ten HTML files carry `aria-hidden="true"` (they always accompany text), as do the two built by JS (`ponerIcono()` in `notas.js`, the copy button in `scriptpass.js`). `test_fragmentos.js` guards both.
- The logo `<img>` already has `alt`, `width` and `height`; the navbar toggler is a `<button>` with `aria-label` plus Bootstrap's `<span class="navbar-toggler-icon">` (not an `<i>`).
- **Live regions:** every result box that JS fills is `aria-live="polite"` — `#result` (`clases.html` and `subneting.html`), `#resultado-conversor` (`conversor.html`), `#passwordResult` (`pass.html`) and `#taskList` (`tareas.html`); the chat log uses `role="log"` + `aria-live="polite"`.
- **Headings:** `index.html` and each fragment carry exactly one `<h1>` (size preserved with Bootstrap's `.h2`/`.h5`/`.h6` classes, so the design does not change); `subneting.html` no longer jumps from `h3` to `h6`.
- `img/` holds only `logo.jpg`: `clases.jpg` and `4-clases-de-redes.webp` were deleted because no HTML/CSS/JS referenced them (they remain in git history if ever needed).

## Conventions

- All UI text, comments, and alerts are in **Spanish**. Maintain this for any new content.
- **Language rule:** everything (code comments, docs, commit messages, chat replies) is written in **Spanish**; English only when strictly unavoidable (technical names, identifiers, third-party terms). No other languages.
- The site itself has no build step and no test suite; the only dev tooling is the lint/format `package.json` described below, executed by a GitHub Actions workflow (`.github/workflows/check.yml`, Node 24, `npm ci` + `npm run check`).
- `.agents/` and `skills-lock.json` are local AI-skills config installed by `autoskills` (accessibility, seo, frontend-design, deploy-to-vercel). They are **git-ignored** (see `.gitignore`): they are not part of the site and can be regenerated with `npx autoskills`.

## Tests

- The repo has its **own verification suites** in `tests/` (plain node scripts, no framework): `test_redes.js` (IP utilities, class detection, the three subneting calculators, the capacity mode and the tutor breakdown), `test_flujo.js` (tool flows over `localStorage` with a stub DOM), `test_fragmentos.js` (fragments are pure markup, every `data-vista` is in `VISTAS`, init functions are registered, ids the JS looks up exist, icons carry `aria-hidden`, skip-link target, `lang`/description/SRI), `sync_check.js` (the duplicated portada keeps the same tags and visible words) plus `test_sync_negativo.js` (that checker must fail when it should), `test_copia_fallback.js` (clipboard `execCommand` fallback), `test_dom_real.js` (**jsdom**: real DOM, `nodosDesdeHTML`, XSS safety, delegated navigation, skip link, subneting mode switch), `test_conversor.js` (**jsdom**: the base converter — per-base validation, the four equivalences, the 32-bit cap, the old octal-vs-hexadecimal bug, Enter key and the help/length swap on base change), `test_chat.js` (**jsdom** over the real `index.html`: the rule engine and its normalisation, that every suggested question reaches its own intent, that every `vista` exists in `VISTAS`, the `data-vista` button loading the fragment, the panel closing on navigation, the widget surviving a fragment swap, XSS safety and persistence) and `check_balance.js` (tag balance per HTML file; `index.html` is run with the `balance` argument because it legitimately carries doctype/head/link).
- `npm test` runs them through `tests/run.js`, which launches each suite with the repo root as its working directory, prints one line per suite and the whole output only when one fails. `npm run check` = `lint` + `format:check` + `test`.
- Suites that read repo files start with `process.chdir(<repo root>)`, so they work from any cwd; `test_redes.js` and `test_dom_real.js` default to the repo path (an argument still overrides it). The stub DOMs in `test_redes.js`/`test_flujo.js` also define `documentElement` and `localStorage`, because `redes.js` initialises the light/dark theme at load.
- `jsdom` is a devDependency used **only** by the DOM suites (`test_dom_real.js`, `test_conversor.js`, `test_chat.js`). The `tests/**` block in `eslint.config.mjs` turns off `no-console`, `no-eval`, `complexity` and `max-lines-per-function`: the suites print their own report and `test_redes.js`/`test_flujo.js` load `redes.js` with `eval` to reach its functions. `test_chat.js` evaluates `redes.js` + `chatDatos.js` + `chat.js` in a **single** `win.eval` so `chat.js` can see the `const VISTAS` of `redes.js` (a top-level `const` lives in the script's lexical scope, not on `window`), and its last expression returns the knowledge base to the test.
- Some stderr noise is expected: `test_flujo.js` deliberately feeds corrupt JSON so the site's `leerX()` helpers log their `console.error` from the `catch` blocks. `tests/run.js` takes its summary from stdout for that reason.

## Lint and format (local tooling)

- Root `package.json` is **dev-only** (the site needs no build). Scripts: `npm run lint` = `lint:js` (eslint) + `lint:css` (stylelint) + `lint:html` (html-validate); `npm run format` = `prettier --write .`; `npm run format:check` verifies without writing; `npm test` = `node tests/run.js`; `npm run check` = `lint` + `format:check` + `test` (the single "everything is fine" command).
- **CI:** `.github/workflows/check.yml` runs `npm ci` + `npm run check` on `ubuntu-latest` with Node 24 on every push to `main`/`herramientas`, on every pull request and on `workflow_dispatch`. There is no build or deploy step: the workflow only validates. The suites use no absolute Windows paths and no `process.platform` branches, so they behave the same on Linux.
- Configs: `eslint.config.mjs` (flat config; `no-restricted-syntax` bans `innerHTML`/`outerHTML` assignments and `insertAdjacentHTML`, and the message cites `JS-02`; the only sanctioned sink is `nodosDesdeHTML()` in `redes.js`; a final `tests/**` block relaxes the rules for the verification suites), `.stylelintrc.json`, `.htmlvalidate.json`, `.prettierrc` (double quotes, semicolons, printWidth 100, Prettier's default 2-space indent), `.prettierignore`.
- The first `npm run format` rewrote essentially every line of the site: Prettier reindented the markup from the original 4 spaces per level to 2, and wrapped the long attribute lists. It is a whitespace-only change (same tags, same visible words), but the diff is a full-file rewrite, so keep it in its own commit.
- Prettier formats the whole site **and** the root `*.md`. `.prettierignore` excludes `node_modules`, `package-lock.json`, `.agents/`, `skills-lock.json`, `.opencode/` and `.vscode/`: the skill rule files and local agent config are read as instructions and must not be rewritten.
- **Prettier vs html-validate:** they conflict by default. Prettier emits `<!doctype html>` and self-closing voids (`<meta ... />`); `html-validate:recommended` requires `<!DOCTYPE html>` and omitted end tags (14 errors on a freshly formatted `index.html`). Resolved in `.htmlvalidate.json` with `doctype-style: ["error", {"style":"lowercase"}]` and `void-style: ["error", {"style":"selfclosing"}]`. Changing one tool means revisiting the other.
- **Line endings (CRLF vs LF):** the repo stores LF, but `core.autocrlf=true` (Windows) checks every git-written file out as CRLF, and Prettier's default `endOfLine: "lf"` rejects that (it flagged exactly the 6 files git rewrote during the message rewrite; a fresh clone would flag all of them). Fixed by committing `.gitattributes` with `* text=auto eol=lf` and renormalizing the working tree (`git rm --cached -r . && git reset --hard`). Weakening that rule breaks `npm run format:check` on Windows.
- Remaining **real** debt (not formatting artifacts): **eslint has 0 errors** — the `innerHTML`/`JS-02` debt is closed (user data via `createElement`/`textContent`; generated markup and the local fragments through the single `nodosDesdeHTML()` helper). What is left are eslint **warnings** (complexity, max-lines, `console`). `stylelint` is **clean**: colours use modern notation (`rgb(… / …%)`), hex is short (`#fff`), class names are kebab-case, selectors stay at or below `0,3,0`, and the only `!important` is the `prefers-reduced-motion` block, wrapped in `stylelint-disable declaration-no-important` / `stylelint-enable`. `html-validate` is **clean over all 9 HTML files** (fragments' form controls have labels; buttons declare `type`). The inline edit form `notas.js` builds with `createElement` (`edit-titulo`, `edit-contenido`, `edit-fecha`) is invisible to html-validate, so its fields carry `.visually-hidden` `<label for=…>` elements and a jsdom check asserts the association. **HTML-05 is closed**: none of the 9 HTML files has an inline `style=` or `on*=` attribute (44 inline handlers removed in the navigation step).
- **Tool stylesheet conventions (enforced by stylelint):** class names are kebab-case (`.task-item`, `.toggle-button`, `.edit-button`, `.delete-button`, `.task-text`) and the JS that creates those nodes (`scriptTareas.js`) must use the same strings — change both together. Selectors scope under the `.vista-*` wrapper and keep specificity ≤ `0,3,0`, so the element selector is dropped: `.vista-notas .editar:hover`, not `.vista-notas .nota button.editar:hover`.

- `/revisar <ruta>` reviews front-end code. It is defined by `.opencode/commands/revisar.md`, which selects the `revisar` agent and loads the `revision-frontend` skill.
- The `revisar` agent (`.opencode/agents/revisar.md`, `mode: all`) is read-only: `edit` is denied, `shell` is allowed so the skill's linters (eslint / stylelint / html-validate) can run.
- The skill lives in `.opencode/skills/revision-frontend/` (`SKILL.md` + `reglas-*.md`). Its **id is derived from the folder name** (not the frontmatter `name`), so the folder must stay `revision-frontend`; the previous folder `revision-fontend` produced the wrong id `revision-fontend`.
- Gotcha: a command whose `agent:` refers to a non-existent agent is listed normally but fails when run with `Error: Agent not found: <id>` (this is what broke `/revisar`). Both `.opencode/skill` and `.opencode/skills` (and global `~/.config/opencode/skill(s)`) are scanned by OpenCode v2.0.29; the canonical plural form is used here.
