# MEMORY.md

## Project Overview

Static educational site about IP networks (Redes IP) plus classroom tools (generador de contraseñas, tareas, notas, agenda). Pure HTML/CSS/JS — the site has no build step, no framework and no CI; a root `package.json` holds **dev-only** tooling (lint/format plus the test runner, see below). Must be served over HTTP (`python -m http.server`): navigation uses `fetch()` and breaks on `file://`.

## Architecture

- `index.html` is the **only real entry point** and the only place with `<link>`/`<script>` tags (Bootstrap CDN + `scripts/*.js` + `css/*.css`). Its semantic skeleton is `<header>` (navbar) + `<main id="cuerpo">` + `<footer>`, a single `h1`; `#cuerpo` keeps its `id` so `cargarFragmento()` keeps working when the wrapper changed from `div` to `main`. The navbar's two dropdown toggles are native `<button type="button">` (not `<a role="button" href="#">`), which is what html-validate's `prefer-native-element` demands; Bootstrap 5.3's `.nav-link` already resets the button's `background`/`border`, so it looks the same.
- **Sync invariant:** the whole home portada (hero + cards + guide) in `inicio.html` is duplicated as the initial content of `#cuerpo` in `index.html`. Both copies must keep the **same tags and the same visible words** (character-for-character equality no longer holds: Prettier lays each copy out with different whitespace because they sit at different indentation levels, which does not change the render). Any edit to the portada must be applied twice.
- `inicio.html`, `teoria.html`, `clases.html`, `subneting.html`, `pass.html`, `tareas.html`, `notas.html`, `agenda.html` are **pure-markup fragments** (no doctype/head/body/link/script) injected into `#cuerpo` by `cargarFragmento()` in `scripts/redes.js`. `teoria.html` is the theory tutorial (IPv4 basics, classes A–E, mask/CIDR, subneting with the `200.3.25.0/24 → /27` example, private/public addresses per RFC 1918, and a "Más lectura" list of external links). Its menu link ("Teoría") replaced the old paid Platzi link.
- **Key gotcha:** `<script>` tags inside an injected fragment never execute (fragments are parsed with `Range.createContextualFragment`, which does not run scripts either). That is why `cargarFragmento()` calls `inicializarFragmento(archivo)` after injection, which runs `prepararValidacionIP()` plus the per-fragment init function: `iniciarClases()`, `iniciarSubneting()`, `iniciarPass()`, `iniciarTareas()`, `cargarNotas()`. New fragment with JS → register it there.
- **Navigation (HTML-05 closed):** there are **no inline handlers** in the markup. A single delegated `click` listener on `document` (`prepararNavegacion()` in `redes.js`, registered once at load, at the end of the file) resolves any element with `data-vista`, translates it through the `VISTAS` map (vista id → file) and calls `cargarFragmento()`. Because it lives on `document` it keeps working for every fragment injected later; `marcarVistaActiva()` only toggles `.active`/`aria-current="page"` on `.navbar-nav [data-vista]` links, so the portada links can share `data-vista` without getting highlighted (Bootstrap's `.btn.active` would restyle them). Tool controls are wired by `id` in the init functions (`btn-ver-clase` in `clases.html`; `maskSelect`, `btn-clase`, `btn-mascara`, `btn-redes`, `btn-hosts` in `subneting.html`; `btn-guardar` and the already-JS-bound `btn-cargar` in `notas.html`).
- Tool scripts must not run DOM code at load time (elements do not exist yet); each init function attaches its listeners (`addEventListener`, or `.onclick =` when the same node is repainted and must not accumulate listeners).
- `scripts/`: `redes.js` (IP utilities, class detection, subneting calculators, tutor mode, **navigation** — the `VISTAS` map + the delegated click listener —, **and the site's single HTML sink**: `nodosDesdeHTML()` — a `Range.createContextualFragment` wrapper — plus `pintarHTML()`/`escribirResultado()`; only generated markup, never user data, goes through it), `scriptpass.js` (password generator + copy-to-clipboard with a `navigator.clipboard` → `execCommand('copy')` fallback for insecure contexts, i.e. http on the LAN), `scriptTareas.js`, `notas.js`.
- **Persistence:** the tools save data in `localStorage` as JSON — keys `contrasenas` (`[{login, password}]`), `tareas` (`[{id, texto, completada}]`) and `notas`. Pattern: `leerX()`/`escribirX()` helpers with `try/catch` (private mode/quota), init function reloads from storage and repaints after every mutation. Stored passwords are plain text in the browser (classroom use only — noted in the UI). Rendering uses `createElement`/`textContent`, never `innerHTML` with user data (password charset contains `<`/`>`).
- `css/`: unified dark "NOC" theme. `tema.css` holds design tokens (`--red-*`, including the `--red-gradient` cian→teal accent) and overrides Bootstrap CSS variables (`data-bs-theme="dark"` on `<html>`, cyan accent, fonts **IBM Plex Sans** body + **IBM Plex Mono** data via `--red-font-body`/`--red-font-mono`); `estilos.css` is the layout (navbar, footer, agenda) + the **home portada**: a two-column hero (`.hero-redes`) with the IP-address signature (`address-signature`, octeto blocks), data chips (`.hero-chips`/`.chip`) and a hand-drawn inline SVG network illustration (`.hero-art`) whose data-flow packet animates along a path (offsets respected; disabled by the global `prefers-reduced-motion` rule) and whose mono labels take their color from the `.hero-svg-accent` / `.hero-svg-muted` classes instead of inline `style=`, plus the "Explora el sitio" feature cards (`.feature-card`, `.icon-circle`, `.card-link`, `.tool-pill`) and the three-step "¿Por dónde empiezo?" guide (`.step`/`.step-num`). `stylepass.css`, `tareas.css`, `notas.css` are scoped under `.vista-pass` / `.vista-tareas` / `.vista-notas` (their fragment wrapper) so `body`/`button`/`input`/`.container` rules don't leak site-wide. Layout uses two systems: `.panel` (slab, elevated — interactive tools) and `.field` (flat, hairline — explanatory content). `normalize.css` was removed (Bootstrap Reboot covers it). The whole home portada (hero + cards + guide) on `inicio.html` is duplicated as the initial content of `#cuerpo` in `index.html` and must stay in sync. Table headers are sentence case (no uppercase); `:focus-visible` and `prefers-reduced-motion` are handled in `tema.css`.
- Subneting is **classful**: classes A/B/C only, contiguous masks ≥ the class default, at least 2 host bits. Listings use 32-bit arithmetic (no manual carry).

## Dependencies

- Bootstrap 5.3.8, Bootstrap Icons and Google Fonts **IBM Plex Sans** + **IBM Plex Mono** (CDN). jQuery is not used.

## Accessibility and SEO

- `index.html` (the only entry point) carries `<html lang="es">` and a `<meta name="description">` (133 characters). All three jsDelivr resources — `bootstrap@5.3.8/dist/css/bootstrap.min.css`, `bootstrap-icons@1.11.3/font/bootstrap-icons.min.css` and `bootstrap@5.3.8/dist/js/bootstrap.bundle.min.js` — carry **SRI** (`integrity="sha384-…"` + `crossorigin="anonymous"`). Bumping a CDN version means recomputing the hash (`node -e` + `crypto`, over the response bytes the browser receives) or the browser blocks the asset. Google Fonts cannot take SRI (the CSS varies per user agent).
- **Skip link:** `<a class="skip-link" href="#cuerpo">` is the first node in `<body>`; `.skip-link` (in `estilos.css`, using theme tokens) is `position: fixed` off-screen and slides in on `:focus`, and `<main id="cuerpo">` has `tabindex="-1"` so it can actually take the focus. The delegated navigation listener ignores it (it has no `data-vista`), so the browser performs the jump.
- **Decorative icons:** the 56 `<i class="bi …">` in the nine HTML files carry `aria-hidden="true"` (they always accompany text), as do the two built by JS (`ponerIcono()` in `notas.js`, the copy button in `scriptpass.js`). `test_fragmentos.js` guards both.
- The logo `<img>` already has `alt`, `width` and `height`; the navbar toggler is a `<button>` with `aria-label` plus Bootstrap's `<span class="navbar-toggler-icon">` (not an `<i>`).
- `img/` holds only `logo.jpg`: `clases.jpg` and `4-clases-de-redes.webp` were deleted because no HTML/CSS/JS referenced them (they remain in git history if ever needed).

## Conventions

- All UI text, comments, and alerts are in **Spanish**. Maintain this for any new content.
- **Language rule:** everything (code comments, docs, commit messages, chat replies) is written in **Spanish**; English only when strictly unavoidable (technical names, identifiers, third-party terms). No other languages.
- The site itself has no build step and no test suite; the only dev tooling is the lint/format `package.json` described below. No CI pipeline.
- `.agents/` and `skills-lock.json` are local AI-skills config installed by `autoskills` (accessibility, seo, frontend-design, deploy-to-vercel). They are **git-ignored** (see `.gitignore`): they are not part of the site and can be regenerated with `npx autoskills`.

## Tests

- The repo has its **own verification suites** in `tests/` (plain node scripts, no framework): `test_redes.js` (IP utilities, class detection, the three subneting calculators, the tutor breakdown), `test_flujo.js` (tool flows over `localStorage` with a stub DOM), `test_fragmentos.js` (fragments are pure markup, every `data-vista` is in `VISTAS`, init functions are registered, ids the JS looks up exist, icons carry `aria-hidden`, skip-link target, `lang`/description/SRI), `sync_check.js` (the duplicated portada keeps the same tags and visible words) plus `test_sync_negativo.js` (that checker must fail when it should), `test_copia_fallback.js` (clipboard `execCommand` fallback), `test_dom_real.js` (**jsdom**: real DOM, `nodosDesdeHTML`, XSS safety, delegated navigation, skip link) and `check_balance.js` (tag balance per HTML file; `index.html` is run with the `balance` argument because it legitimately carries doctype/head/link).
- `npm test` runs them through `tests/run.js`, which launches each suite with the repo root as its working directory, prints one line per suite and the whole output only when one fails. `npm run check` = `lint` + `format:check` + `test`.
- Suites that read repo files start with `process.chdir(<repo root>)`, so they work from any cwd; `test_redes.js` and `test_dom_real.js` default to the repo path (an argument still overrides it).
- `jsdom` is a devDependency used **only** by `test_dom_real.js`. The `tests/**` block in `eslint.config.mjs` turns off `no-console`, `no-eval`, `complexity` and `max-lines-per-function`: the suites print their own report and `test_redes.js`/`test_flujo.js` load `redes.js` with `eval` to reach its functions.
- Some stderr noise is expected: `test_flujo.js` deliberately feeds corrupt JSON so the site's `leerX()` helpers log their `console.error` from the `catch` blocks. `tests/run.js` takes its summary from stdout for that reason.

## Lint and format (local tooling)

- Root `package.json` is **dev-only** (the site needs no build). Scripts: `npm run lint` = `lint:js` (eslint) + `lint:css` (stylelint) + `lint:html` (html-validate); `npm run format` = `prettier --write .`; `npm run format:check` verifies without writing; `npm test` = `node tests/run.js`; `npm run check` = `lint` + `format:check` + `test` (the single "everything is fine" command).
- Configs: `eslint.config.mjs` (flat config; `no-restricted-syntax` bans `innerHTML`/`outerHTML` assignments and `insertAdjacentHTML`, and the message cites `JS-02`; the only sanctioned sink is `nodosDesdeHTML()` in `redes.js`; a final `tests/**` block relaxes the rules for the verification suites), `.stylelintrc.json`, `.htmlvalidate.json`, `.prettierrc` (double quotes, semicolons, printWidth 100, Prettier's default 2-space indent), `.prettierignore`.
- The first `npm run format` rewrote essentially every line of the site: Prettier reindented the markup from the original 4 spaces per level to 2, and wrapped the long attribute lists. It is a whitespace-only change (same tags, same visible words), but the diff is a full-file rewrite, so keep it in its own commit.
- Prettier formats the whole site **and** the root `*.md`. `.prettierignore` excludes `node_modules`, `package-lock.json`, `.agents/`, `skills-lock.json`, `.opencode/` and `.vscode/`: the skill rule files and local agent config are read as instructions and must not be rewritten.
- **Prettier vs html-validate:** they conflict by default. Prettier emits `<!doctype html>` and self-closing voids (`<meta ... />`); `html-validate:recommended` requires `<!DOCTYPE html>` and omitted end tags (14 errors on a freshly formatted `index.html`). Resolved in `.htmlvalidate.json` with `doctype-style: ["error", {"style":"lowercase"}]` and `void-style: ["error", {"style":"selfclosing"}]`. Changing one tool means revisiting the other.
- **Line endings (CRLF vs LF):** the repo stores LF, but `core.autocrlf=true` (Windows) checks every git-written file out as CRLF, and Prettier's default `endOfLine: "lf"` rejects that (it flagged exactly the 6 files git rewrote during the message rewrite; a fresh clone would flag all of them). Fixed by committing `.gitattributes` with `* text=auto eol=lf` and renormalizing the working tree (`git rm --cached -r . && git reset --hard`). Weakening that rule breaks `npm run format:check` on Windows.
- Remaining **real** debt (not formatting artifacts): **eslint has 0 errors** — the `innerHTML`/`JS-02` debt is closed (user data via `createElement`/`textContent`; generated markup and the local fragments through the single `nodosDesdeHTML()` helper). What is left are eslint **warnings** (complexity, max-lines, `console`). `stylelint` is **clean**: colours use modern notation (`rgb(… / …%)`), hex is short (`#fff`), class names are kebab-case, selectors stay at or below `0,3,0`, and the only `!important` is the `prefers-reduced-motion` block, wrapped in `stylelint-disable declaration-no-important` / `stylelint-enable`. `html-validate` is **clean over all 9 HTML files** (fragments' form controls have labels; buttons declare `type`). The inline edit form `notas.js` builds with `createElement` (`edit-titulo`, `edit-contenido`, `edit-fecha`) is invisible to html-validate, so its fields carry `.visually-hidden` `<label for=…>` elements and a jsdom check asserts the association. **HTML-05 is closed**: none of the 9 HTML files has an inline `style=` or `on*=` attribute (44 inline handlers removed in the navigation step).
- **Tool stylesheet conventions (enforced by stylelint):** class names are kebab-case (`.task-item`, `.toggle-button`, `.edit-button`, `.delete-button`, `.task-text`) and the JS that creates those nodes (`scriptTareas.js`) must use the same strings — change both together. Selectors scope under the `.vista-*` wrapper and keep specificity ≤ `0,3,0`, so the element selector is dropped: `.vista-notas .editar:hover`, not `.vista-notas .nota button.editar:hover`.

- `/revisar <ruta>` reviews front-end code. It is defined by `.opencode/commands/revisar.md`, which selects the `revisar` agent and loads the `revision-frontend` skill.
- The `revisar` agent (`.opencode/agents/revisar.md`, `mode: all`) is read-only: `edit` is denied, `shell` is allowed so the skill's linters (eslint / stylelint / html-validate) can run.
- The skill lives in `.opencode/skills/revision-frontend/` (`SKILL.md` + `reglas-*.md`). Its **id is derived from the folder name** (not the frontmatter `name`), so the folder must stay `revision-frontend`; the previous folder `revision-fontend` produced the wrong id `revision-fontend`.
- Gotcha: a command whose `agent:` refers to a non-existent agent is listed normally but fails when run with `Error: Agent not found: <id>` (this is what broke `/revisar`). Both `.opencode/skill` and `.opencode/skills` (and global `~/.config/opencode/skill(s)`) are scanned by OpenCode v2.0.29; the canonical plural form is used here.
